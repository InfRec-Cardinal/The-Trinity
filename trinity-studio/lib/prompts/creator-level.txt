OUTPUT CONTRACT

JSON uses double-quoted keys and string delimiters; no trailing commas, undefined, placeholders or ellipses.

The module MUST export exactly:

The ui object is the ONLY way to build the scene and define interaction. Use only these members:
  ui.THREE                     the three.js module (for Color, Vector3, etc. if needed)
  ui.camera                    the scene PerspectiveCamera; set camera.position and camera.lookAt in draw()

  ui.ball(x,y,z,r,color)       add a matte sphere, returns the mesh
  ui.text(label,x,y,z,size,color?) add a sprite text label; optional color MUST be a CSS color string
                             such as '#eef6f3', never a numeric hex integer (unlike box/ball colors)
  ui.command(label, fn)        register a named action; label must be unique; fn runs when taken
  ui.number(label,id,value,min,max)  expose an integer input field
  ui.choice(label,id,options)  expose a choice field over string options
  ui.value(id) / ui.index(id)  read a field's current value / option index
  ui.say(text) / ui.overlay(text)   set the status line / the public overlay text
  ui.step(message, fn)         run one budget-costing action; ends the episode when budget is spent
  ui.finish(ok, message)       end the episode, ok=true means success
  ui.isEnded() / ui.steps()    episode state
  ui.redraw()                  re-render after changing the scene

Rules the module MUST follow:
- No imports, no require, no fetch/network, no filesystem, no process/env, no timers, no eval, no global
  state outside the createLevel closure. Everything lives in closure-local variables.
- draw() is called to (re)render: it should clear nothing itself (the host clears the group before each
  draw), position the camera, draw the current scene with ui.box/ui.ball/ui.text, call ui.overlay(...)
  with the public text, and re-register ui.command(...) for every currently-available action. The host
  calls draw() again after each action. It clears BOTH the command registry and the input field registry
  before every draw. Re-register ui.command, ui.number and ui.choice inside draw() every time they are
  needed. Registering inputs only in createLevel's initialization loses them before the first action.
  Read ui.value/ui.index inside the action callback, before the host redraws; action args refer to the
  registered field ids. Do not implement actions with missing fields or silently substitute an answer
  when an input is absent. ui.step already redraws after its callback; do not redraw inside that callback.
- Hidden state (answers, layouts, solutions) stays in closure variables and is NEVER drawn once it should
  be hidden and NEVER put into ui.overlay or ui.say text.
- Wrap each costing action's body in ui.step(message, fn); free actions call ui.redraw() directly.
- Randomize per build using a small self-contained PRNG seeded from variant (do not call Math.random in a
  way that breaks reproducibility — a simple seeded LCG in the closure is fine). Read difficulty knobs
  from the integer `variant` or default them as the brief says.
- Call ui.finish(true/false, ...) exactly at the design's terminal success/failure conditions.
- Keep the visual style clean and schematic as the brief describes.

Implement the supplied design faithfully. The module must be valid modern JavaScript that parses with
